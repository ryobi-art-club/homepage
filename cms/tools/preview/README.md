# CMS ローカルプレビュー

管理画面（`Ui.html` と、そこに埋め込む画面のスクリプト `UiCore.html` など5つと `UiStyles.html`）を、GAS にデプロイせずに手元のブラウザで確認するための道具です。
見た目の調整を、`clasp push` の前に確認できます。

- コマンドは `cms/` のフォルダで実行します。
- このフォルダは `.claspignore` で除外しているので、GAS には送られません。
- サンプルデータで表示します。Google には一切接続しません。
- 保存・公開・アップロード・削除・目録の読み込み・誤字チェックは、ブラウザのメモリ上で成功したことにします（[`mock-backend.js`](mock-backend.js)）。ページを再読み込みすると元に戻ります。目録の読み込みは、どのファイルを選んでもサンプルの目録を返し、誤字チェックは最初の3項目に必ず指摘を付けます。

## 1. プレビューを作る

```powershell
node tools/preview/build.cjs
```

`tools/preview/out/preview.html` をブラウザで開くと、ログイン後の画面が表示されます。
URL の末尾に `#login` を付けて開くと、ログイン画面から始まります。確認コードは何を入れても通ります。
管理者へのエラー自動通知の結果は、URL に `?notify=sent` のように付けて切り替えられます（`sent` 通知済み / `duplicate` 通知済みの重複 / `limit` 上限 / `failed` 失敗 / `pending` 同じ通知が送信中（未通知の案内） / 付けなければ `not_configured` 未設定）。開いたあとでも、ブラウザのコンソールで `MOCK_BACKEND.notifyMode = 'sent'` と入力すれば切り替わります。
別の人の公開は `PREVIEW_DATA.bootstrap.state.baseVersion = 'another-publication'` で再現できます。画面の `appState.state.baseVersion` は変えずに公開すると止まり、下書きを保存・読み込みしても元の基準が残ります。基準のない既存下書きは、その下書きの `payload.baseVersion` を削除してから読み込みます。競合時の「編集内容を控える」は見本の文章・作品情報・画像参照を JSON としてダウンロードします。
公開の失敗は `MOCK_BACKEND.publishFailure = 'before-save'`（保存前）または `'github'`（保存・全下書き削除後のサイト更新起動時）で試せます。`''` に戻すと成功します。`MOCK_BACKEND.sessionExpired = true` にすると、編集中に下書き保存したときの期限切れを試せます。どれも見本のメモリ上だけの再現です。
画面のスクリプトや `UiStyles.html` を変更したら、もう一度実行してください（1秒かかりません）。
スマホの表示は、Chrome の検証ツールでデバイスモードにして、機種（iPhone SE など）を選んで確認できます。本番の `doGet()` と同じく、画面の幅に合わせる指定（viewport）を入れてあります。

## 2. 全機能を動かしてスクリーンショットを撮る（任意）

Chrome が必要です。Excel 読み込みの確認で SheetJS を CDN から取得するため、ネット接続も必要です。

```powershell
npm install --prefix tools/preview
node tools/preview/shoot.cjs
```

Chrome が標準の場所にない場合は `--chrome <chrome.exe のパス>` を付けてください。

ログインから公開まで、CMS のボタンをひととおり押します（`confirm` は公開の取り消しを確かめる1回だけ「キャンセル」、ほかは「OK」）。
スクリーンショットは、表示が崩れる可能性のある画面だけを `tools/preview/out/shots/` に保存します。
何度撮っても同じ画像になるよう、時刻（2026年10月31日 12:00）と乱数を固定し、動き（アニメーション）を止め、上の表示欄の文言を出し終えてから撮ります。
画面がサーバーに送った内容（関数の名前と引数）は `tools/preview/out/server-calls.json` に書き出します。

- 全タブ（デスクトップ・スマホ）、ログイン画面、確認コードの入力画面
- 画像ダイアログ（活動記録・展示会の目録読み込み）、誤字チェックのダイアログ（デスクトップ・スマホ）
- 状態履歴パネル、エラー表示（長いエラー文、スマホ、画像ダイアログ内、ログイン画面）
- 別の人の公開後の下書き保存・再読込、基準のない既存下書き、競合で入力・公開データを保つこと、控えの実ダウンロードと内容照合
- 下書きの有無による公開確認の補足、公開確認の取り消し、保存前と保存後の公開失敗、編集中の期限切れ（入力と画像参照が残り、自動で再読み込みしないこと）

撮らない操作（項目の追加・削除・並べ替え、アップロードなど）は、動かしてエラーが出ないかだけを確かめます。
最後に次の内容を表示します。問題が見つかった場合は終了コードが 1 になります。

- SheetJS を整合性チェック（SRI）付きで読み込めたか
- 画面のスクリプトの関数のうち実際に動いた数と、一度も動かなかった関数の名前
- 画面で発生したエラー

CMS に機能を足したら、一度も動かなかった関数に出てこないことを確認し、出てきたら `shoot.cjs` に操作を追加してください。

## 3. 見た目と動きが変わっていないか比べる（作りを整理するとき）

見た目や動きを変えないはずの作業（書き方の整理など）では、作業の前と後で撮影の結果を比べます。`pngjs` と `pixelmatch` を使います（`npm install --prefix tools/preview` で入ります）。

```powershell
node tools/preview/shoot.cjs
node tools/preview/compare.cjs --save <控えのフォルダ>   # 作業の前に、撮影の結果を控えに取る
（作業する）
node tools/preview/build.cjs
node tools/preview/shoot.cjs
node tools/preview/compare.cjs <控えのフォルダ>          # 控えと比べる
```

画像は1画素ずつ、サーバーに送った内容は名前の並び順を除いて1文字ずつ比べます。違いがあれば、違う画素に印を付けた画像を `tools/preview/out/diff/` に書き、終了コード 1 で終わります。
控えのフォルダは、リポジトリの外（一時フォルダなど）に置いてください。

## サンプルデータについて

[`sample-data.cjs`](sample-data.cjs) には、本番で表示が崩れやすいケースをわざと入れています。

- 長いタイトル・説明文・会場名、長い URL を含む本文
- 作品 24 点の展示会（縦長・横長・パノラマが混在、作品名や作者名が空の作品あり）
- 画像 7 枚の活動記録（「+3」表示）、画像のない取り組み事例
- 非公開の記事・展示会・年度、長い名前の部員による下書き

本番で表示崩れが見つかったら、同じ条件のデータをここに追加しておくと、次から手元で確認できます。
