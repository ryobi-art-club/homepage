# 一から作り直す手順

Google のアカウントや GitHub の設定を失ったときなど、システムを最初から用意し直すときに、上から順に行います。

**すでにあるものは作り直しません。** 各手順の「**あるか確かめる**」で、もうあって動いているものは飛ばしてください。作り直すと ID・URL・鍵が変わり、それを書いた所（スクリプト プロパティ、GitHub のシークレット、部員に伝えた管理画面の URL）を全部直すことになります。一部だけが動かないときは、先に [困ったとき（症状から探す）](troubleshooting.md) で原因を探してください。

- 作り直したものの古い方は、新しい方で動くのを確かめるまで消しません。
- 手順の中で使う値（ID・鍵）は、スクリプト プロパティかシークレットに入れるだけにし、リポジトリには書きません（[公開してはいけないものの確認](development.md#公開してはいけないものの確認)）。

1. **開発用の Google アカウントを用意する**
   - あるか確かめる：ログインできるなら、そのまま使う（[アカウントと権限](operations.md#アカウントと権限)）。
   - ないとき：部で管理するアカウントを新しく作る。個人の大学アカウントは使わない。以下の Google 関係のものは、すべてこのアカウントで作る。
2. **スプレッドシートを2つ用意する**
   - あるか確かめる：GAS のスクリプト プロパティ `CONTENT_SPREADSHEET_ID`・`ALLOWLIST_SPREADSHEET_ID` の ID で開けるなら飛ばす。
   - ないとき：コンテンツ用（中は空でよい。シートは自動で作られる）と、許可リスト用（`allowlist` シートに `name` / `email` の見出しと、最初の管理者の行を書く）を作る。
3. **Drive にルートフォルダを4つ用意する**（新歓・活動記録・展示会・ご依頼）
   - あるか確かめる：スクリプト プロパティ `ROOT_…_FOLDER_ID` の ID で開けるなら飛ばす。
   - ないとき：4つ作る。共有は「制限付き」のままにする（[Google Drive のフォルダ構成](reference/cms.md#google-drive-のフォルダ構成)）。
4. **GAS プロジェクトを用意して、コードを送る**
   - あるか確かめる：<https://script.google.com/> に、`cms/.clasp.json` の `scriptId` のプロジェクトがあるなら、新しく作らない（`scriptId` を書き換えると送り先が変わり、本番の管理画面は古いまま残る）。
   - ないとき：<https://script.google.com/> で新しいプロジェクトを作り、「プロジェクトの設定」の「スクリプト ID」を `cms/.clasp.json` の `scriptId` に書いてコミットする。
   - どちらのときも：[開発の環境を整える（最初に1回）](development.md#開発の環境を整える最初に1回) の 6（Google Apps Script API をオンにし、clasp に開発用アカウントでログイン）をしてから、リポジトリの直下で `clasp -P cms push`。
5. **Gemini の API キーを用意する**
   - あるか確かめる：スクリプト プロパティ `GEMINI_API_KEY` が入っていて、目録の読み取りが動くなら飛ばす。
   - ないとき：開発用アカウントで <https://aistudio.google.com/> を開き、無料枠の API キーを作る（[設計の判断](decisions.md)）。
6. **GitHub の組織とリポジトリを用意する**
   - あるか確かめる：組織 `ryobi-art-club` とリポジトリ `homepage` があり、自分がオーナーなら飛ばす。
   - ないとき：組織とリポジトリを作り、このリポジトリの中身を push する。組織のオーナーは2人以上にする（[アカウントと権限](operations.md#アカウントと権限)）。
7. **GitHub App を用意する**
   - あるか確かめる：組織の「Settings」→「GitHub Apps」に `Ryobi-Homepage-Deployer` があり、このリポジトリにインストールされているなら、新しく作らない。スクリプト プロパティ `GH_APP_ID`・`GH_INSTALLATION_ID`・`GH_PRIVATE_KEY` が入っていれば、この手順はまるごと飛ばす。
   - ないとき：組織の「Settings」→「Developer settings」→「GitHub Apps」で App を作り（権限は `Actions: Read and write`）、このリポジトリにインストールする。
   - 値の見つけ方：App ID は App の設定画面の上にある。インストール ID は、組織の「Settings」→「GitHub Apps」→ App の「Configure」を開いたときの URL の末尾の数字。秘密鍵は App の設定画面の「Generate a private key」で作る（作るたびに鍵が1つ増え、前の鍵も使えるまま残る。使わなくなった鍵は消す）。
8. **スクリプト プロパティを設定する**（[Script Properties（設定値）](reference/cms.md#script-properties設定値)）
   - すでに入っている値は、上の手順で作り直したものだけを書き換える。
9. **ウェブアプリとしてデプロイする**
   - あるか確かめる：GAS エディタの「デプロイ」→「デプロイを管理」に本番のデプロイがあるなら、「新しいデプロイ」は作らない（管理画面の URL が変わる）。コードを変えたときは [管理画面を反映する](development.md#管理画面を反映する) の手順で版を上げる。
   - ないとき：「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。実行するユーザーは「自分」、アクセスできるユーザーは「Google アカウントを持つ全員」。表示された URL が管理画面の URL です。初回は権限の許可を求められます。
10. **サービスアカウントを用意する**
    - あるか確かめる：[Google Cloud Console](https://console.cloud.google.com/) の「IAM と管理」→「サービス アカウント」にあり、GitHub の「Actions」でサイトのビルドが成功しているなら、鍵を作り直さず飛ばす。
    - ないとき：プロジェクトを作り、「Google Sheets API」と「Google Drive API」を有効にする。サービスアカウントを作り、鍵（JSON）を作ってダウンロードする。鍵ファイルはリポジトリの外に置き、シークレットに登録したら手元からは消す。
11. **サービスアカウントに共有する**：コンテンツ用スプレッドシートと Drive の4つのルートフォルダを、サービスアカウントのメールアドレスに「閲覧者」で共有する（共有済みなら飛ばす）。
12. **GitHub Pages を有効にする**：リポジトリの「Settings」→「Pages」で、Source を「GitHub Actions」にする（なっていれば飛ばす）。
13. **シークレットを登録する**（[GitHub Actions とシークレット](reference/site.md#github-actions-とシークレット)）：作り直したもの（コンテンツ用スプレッドシートの ID、サービスアカウントの鍵）だけを入れ替える。
14. **公開してはいけないものの確認を有効にする**：「Push protection」を有効にする（[開発の環境を整える（最初に1回）](development.md#開発の環境を整える最初に1回) の 3。有効なら飛ばす）。
15. **動かしてみる**：管理画面で「公開する」を押し、Actions が成功してサイトが表示されるか確かめる。管理画面の URL が変わったときは、部員に直接伝える（リポジトリには書かない）。
16. **検索エンジンに登録する**
    - あるか確かめる：Google Search Console と Bing Webmaster Tools に、サイトが登録済みなら飛ばす（[検索エンジン（Search Console・Bing）](operations.md#検索エンジンsearch-consolebing)）。オーナーを足すだけなら、今のオーナーが画面から追加する。
    - ないとき：サイトを登録して `sitemap.xml` を送る。所有確認に HTML ファイルを使うときは、`src/verification/` に置いて push し、サイトを作り直す（今あるファイルは、ほかのオーナーの確認に使っているので消さない）。
