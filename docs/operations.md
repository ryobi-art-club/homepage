# 管理者の手順（運用・引き継ぎ・点検）

ホームページを運用する管理者が、ふだんの作業・引き継ぎ・年1回の点検をするときに読みます。

## アカウントと権限

このシステムの権限は、管理を簡単にするため、なるべく少ないアカウントに集めています。

- **開発用の Google アカウント（1つ）**：Google 関係のもの（GAS、スプレッドシート、Drive、Google Cloud、Gemini）はすべてこのアカウントが持っています。
- **サービスアカウント（1つ）**：公開サイトのビルドが、スプレッドシートと Drive を読むためだけに使います。開発用アカウントの Google Cloud プロジェクトの中にあり、IAM の画面から管理できます。
- **GitHub の組織 `ryobi-art-club` のオーナー**：管理者の個人の GitHub アカウントです。

> **このリポジトリは公開されています。** 具体的なアカウント名・メールアドレス・パスワード・鍵は、ここには書かないでください。引き継ぎのときに、管理者から後任へ直接渡します。

| もの | 何に使うか | 持ち主 | 備考 |
|---|---|---|---|
| GAS プロジェクト（管理画面） | 管理画面そのもの。**このアカウントの権限で**シート・Drive の読み書きとメール送信をする | 開発用の Google アカウント | 設定値は GAS エディタの「スクリプト プロパティ」（[Script Properties（設定値）](reference/cms.md#script-properties設定値)） |
| コンテンツ用・許可リスト用のスプレッドシート | ホームページの内容、管理画面にログインできる人の一覧 | 開発用の Google アカウント | サービスアカウントにも閲覧権限を共有している（コンテンツ用） |
| Google Drive の4つのフォルダ | 画像の置き場所（新歓・活動記録・展示会・ご依頼） | 開発用の Google アカウント | サービスアカウントにも閲覧権限を共有している |
| Google Cloud プロジェクト | サービスアカウントと、その鍵の管理 | 開発用の Google アカウント | 鍵（JSON）はこのリポジトリの Actions のシークレットに登録。鍵ファイルはリポジトリに入れない |
| Gemini の API キー | 目録の読み取りと誤字チェック | 開発用の Google アカウント | Google AI Studio で取得した無料枠のキー（[設計の判断](decisions.md)）。スクリプト プロパティ `GEMINI_API_KEY` |
| 管理画面の URL | 部員が管理画面を開く入口 | — | リポジトリには書かない。GAS エディタの「デプロイ」→「デプロイを管理」で、本番のデプロイの「ウェブアプリ」の URL を見る |
| Google Search Console | Google 検索での表示の確認 | 部の公式アカウント（サイトに載せている連絡先）と、開発用の Google アカウントの両方がオーナー | 所有確認のファイルが `src/verification/` に2つあるのはそのため |
| Bing Webmaster Tools | Bing 検索での表示の確認 | 開発用の Google アカウント | |
| GitHub の組織とリポジトリ | ソースコード、GitHub Actions、GitHub Pages | 管理者の GitHub アカウント（組織のオーナー） | |
| GitHub App（`Ryobi-Homepage-Deployer`） | 管理画面が GitHub Actions を起動するため | GitHub の組織（組織のオーナーが管理） | 組織に「インストール」して使う。App ID・インストール ID・秘密鍵はスクリプト プロパティにある |
| エラー通知の宛先 | システム側のエラーが起きたときのメール | 管理者が受け取れるアドレス | スクリプト プロパティ `ERROR_NOTIFY_EMAIL`（任意） |

### 引き継ぎのときに渡すもの

1. **開発用の Google アカウント**：ログイン情報と、2段階認証の手段（バックアップコードを含む）。復旧用のメールアドレスや電話番号が前の管理者の個人のものなら、後任のものに変えてもらう。
2. **GitHub の組織のオーナー権限**：後任の GitHub アカウントを、組織のオーナーに追加してもらう。
3. **GitHub App**（`Ryobi-Homepage-Deployer`）：組織 `ryobi-art-club` の持ち物なので、オーナー権限を渡せばそのまま使える。渡す側も受け取る側も、特にすることはない。
4. **エラー通知の宛先**：スクリプト プロパティ `ERROR_NOTIFY_EMAIL` を後任のアドレスにする。
サービスアカウントの鍵、スクリプト プロパティの値、管理画面の URL、Search Console、Bing Webmaster Tools は、開発用アカウントでログインすれば見られる（作り直せる）ので、個別に渡す必要はありません。

**代わりがいない状態を避ける**：権限を1人に集めていると、その人が急に対応できなくなったとき、誰も直せなくなります。GitHub の組織のオーナーはもう1人（次の管理者の候補など）にも付けておき、開発用アカウントの復旧手段も、特定の個人だけに結びつけないようにしておくと安心です。

### 持ち主のアカウントが使えなくなると止まる

管理画面は「デプロイした人」のアカウント（今は開発用の Google アカウント）の権限で動きます（`appsscript.json` の `executeAs: USER_DEPLOYING`）。そのアカウントが使えなくなると、管理画面は動かなくなります。確認コードのメールも、このアカウントから送られています。

- 持ち主は、個人の大学アカウントではなく、今のように**部で管理する開発用のアカウント**にしておきます。卒業で大学のアカウントが消えると、管理画面が止まってしまうためです。
- やむを得ず持ち主のアカウントを変えるときは、GAS プロジェクト・スプレッドシート・Drive フォルダの持ち主を新しいアカウントに移します。そのあと、新しいアカウントで管理画面をデプロイし直してください（[管理画面を反映する](development.md#管理画面を反映する)）。デプロイし直して管理画面の URL が変わった場合は、部員に新しい URL を伝えます（管理画面の URL は、外の人に入口を知られないよう、部員に直接伝え、リポジトリには書きません）。
- サービスアカウントにスプレッドシートと Drive フォルダが共有されたままか、移したあとに確認します（共有が外れると、サイトのビルドが失敗します）。

## ふだんの運用

### 部員を追加する・外す

1. 許可リスト用スプレッドシートを開き、`allowlist` シートに1人1行で書く。
   | name | email |
   |---|---|
   | 部員の名前 | メールアドレス |
2. 外すときは、その人の行を消す。

**確かめ方**：追加した人に管理画面を開いてもらい、確認コードのメールが届いてログインできれば完了です（登録されていないアドレスにも「送りました」と出るので、メールが届くかで確かめます）。

- `name` は、管理画面の「ログイン中」や公開履歴に表示されます。
- 外した人も、すでにログイン中なら、ログインの有効期限（180分）が切れるまで使えます。
- 管理画面のログインは「Google アカウントでのログイン」と「確認コード」の2段階です。Google アカウントは何でもよく、許可リストに載っているかどうかは確認コードを送るメールアドレスで判定します。

### 年度替わりにすること

- [ ] 許可リストを更新する（新しい担当者を追加、卒業生を外す）
- [ ] 管理画面の「入部希望の方」で、新しい年度を追加する
- [ ] 管理者が交代するなら、[引き継ぎのときに渡すもの](#引き継ぎのときに渡すもの)を行う
- [ ] [定期的な点検](#定期的な点検)をひととおり行う

### エラーの通知メールが届いたら

`ERROR_NOTIFY_EMAIL` を設定していると、システム側のエラー（設定の不備、GitHub との連携の失敗、Google の利用上限など）が起きたときに、メールが届きます。部員が画面からコピーして送ってくる報告文も、同じ形式です。

1. メールの「操作」と「内容」を見て、[困ったとき（症状から探す）](troubleshooting.md)の表で原因を探します。
2. 詳しい記録は、GAS エディタの「実行数」画面にあります（エラーは `console.error` で記録されます）。日時とエラー ID で探せます。
3. 「公開」のエラーでも、**内容はスプレッドシートに保存済み**のことが多いです（GitHub の起動だけが失敗した場合など）。原因を直したら、もう一度「公開する」を押せば反映されます。

### Drive の容量

管理画面のホームに「Drive容量」が出ます。残りが少なくなると、色が変わり、容量を空けられる候補（古い展示会のフォルダなど）が表示されます。

- 削除した項目のフォルダや、展示会で使わなくなった画像は、公開のたびに自動で片付けます（[Google Drive のフォルダ構成](reference/cms.md#google-drive-のフォルダ構成)）。片付けたものは Drive のゴミ箱に入り、30日間は元に戻せます。ゴミ箱の中のファイルも容量に数えられるので、容量が空くのは30日後です。
- 容量は、GAS プロジェクトの持ち主のアカウント全体の容量です（ホームページ以外のファイルも含みます）。

### 固定の文章や画像を変える

管理画面で編集できないもの（紹介文、活動場所、年間スケジュール、画材、連絡先、SNS など）を変える手順です。どこを直すかは、下の表で探します。

1. `src/site_static.json`（画像なら `src/` のファイル）を直す。
2. コミットして push する。
3. 管理画面で「公開する」を押して、サイトを作り直す（push だけでは作り直されません。[公開サイトを反映する](development.md#公開サイトを反映する)）。

**確かめ方**：数分後にサイトを開き、直した所が変わっていれば完了です。

| 内容 | 編集する場所 |
|---|---|
| 展示会・活動記録・新歓カレンダー・ご依頼事例 | 管理画面 |
| 部の名前、トップの見出し、紹介文 | `site_static.json` の `club_name_jp`、`hero_…`、`intro_text` など |
| 各タブの説明文 | `site_static.json` の `exhibitions_static.summary` など |
| 入部希望の方：基本情報・画材・年間スケジュール | `site_static.json` の `recruit_static` |
| ご依頼の方：連絡先 | `site_static.json` の `requests_static` |
| SNS のリンク、コピーライト | `site_static.json` の `social_links`、`copyright` |
| ロゴ、部室の写真 | `src/logo.png`、`src/clubroom.jpg` |
| デザイン・動き | `src/stylesheet.css`、`src/site.js`、`scripts/sitebuild/`（[公開サイトの見た目や動きを変えるとき](development.md#公開サイトの見た目や動きを変えるとき)） |

#### `site_static.json` の項目

| 項目 | 内容 |
|---|---|
| `club_name_jp` / `club_name_en` | 部の名前（日本語・英語） |
| `hero_kicker` / `hero_title` / `hero_subtitle` | トップの小見出し・見出し・説明 |
| `og_url` | サイトの正式な URL（SNS で共有したときの表示、検索エンジン向けの情報、sitemap に使う） |
| `og_image` | SNS で共有したときの画像（`logo.png` または URL） |
| `intro_text` | 紹介文 |
| `information_text` | INFORMATION の説明文 |
| `exhibitions_static.summary` / `activities_static.summary` | 展示会・活動記録タブの説明文 |
| `recruit_static` | 入部希望の方タブ。`headline`（見出し）、`summary`（説明）、`info_points`（基本情報）、`materials`（画材・道具）、`annual_schedule`（年間スケジュール） |
| `requests_static` | ご依頼の方タブ。`summary`、`contact_email`、`contact_instagram`、`contact_x` |
| `social_links` | `instagram` / `x` / `email` |
| `copyright` | フッターの著作権表示 |

**`recruit_static` の中身**

- `info_points`：`label`（項目名）と `text`（内容）の並び。写真を付けるときは `image`（`src/` に置いたファイル名）、地図などへのリンクを付けるときは `link`（`url` と `label`）を足す。
- `materials`：`name`（画材の名前）と `note`（説明）の並び。
- `annual_schedule`：`period`（時期）、`label`（内容）、`accent`（色：`yellow` / `blue` / `green` / `white`）の並び。

**文章の中のリンク**：`hero_subtitle`、`intro_text`、`information_text`、各タブの `summary`、`info_points` の `text` では、`[表示する文字](https://example.com)` と書くとリンクになります。

#### 写真を増やすときの注意

`src/` の画像は、ビルドの最後に `build_site.py` が**ファイル名を指定して** `dist/` にコピーしています（`STATIC_FILES` の `logo.png`、`clubroom.jpg`）。写真を増やしたら、ここにも名前を足してください。足さないと、サイトで画像が表示されません。

### 検索エンジン（Search Console・Bing）

ページは1枚だけなので、ふだんすることはありません。年に1回くらい、検索に出ているかを見る程度で足ります。

- **Search Console のサイトマップが「取得できませんでした」のまま**：サイトを作ったときに `sitemap.xml` を送ってから、ずっとこの表示です。ページは検索に出ている（インデックスされている）ので、そのままにしています。
- **Bing Webmaster Tools の「タイトルが短い」「説明文が短い」**：わざと今の文にしています（[設計の判断](decisions.md)）。文は `scripts/sitebuild/page.py` の `SITE_TITLE`・`SITE_DESCRIPTION` です。
- **Bing Webmaster Tools の「`<img>` に ALT がない」**：ページ先頭のスライドの写真を、飾りとして空（`alt=""`）にしているためと思われます。飾りの画像は空にするのが正しい作りなので、そのままにしています。

## 定期的な点検

年度替わりなど、1年に1回くらいを目安に確認します。

| 項目 | 確認すること | 方法 |
|---|---|---|
| SheetJS（Excel の目録の読み込み） | 新しい版が出ていないか | [cdn.sheetjs.com](https://cdn.sheetjs.com/) を見る。版を上げるときは `UiMedia.html` の `SHEETJS_URL` と `SHEETJS_INTEGRITY`（整合性チェックの値）を一緒に変える。整合性チェックの値は `curl -s <URL> \| openssl dgst -sha384 -binary \| openssl base64 -A` の結果の頭に `sha384-` を付けたもの。変えたら `shoot.cjs` で読み込めるか確かめる |
| Font Awesome（アイコン） | 古すぎないか | 管理画面の `Ui.html` と、サイトの `sitebuild/page.py` で 6.4.2 を使っている。版を上げるときは、両方の URL と `integrity`（整合性チェックの値）を一緒に変える。値は `curl -s <URL> \| openssl dgst -sha512 -binary \| openssl base64 -A` の結果の頭に `sha512-` を付けたもの（[cdnjs](https://cdnjs.com/libraries/font-awesome) のページにも載っている）。変えたら `shoot.cjs` でアイコンが出るか確かめる |
| Gemini のモデル | 提供が終わっていないか | 目録の読み取りや誤字チェックが「モデルが見つからない」などで失敗したら、スクリプト プロパティ `GEMINI_MODEL` に新しいモデル名を書く（すぐ効く）。次にコードを直すときに、`AppConfig.js` の `CONFIG_DEFAULTS` も新しい名前にして、プロパティは消す |
| GitHub App | 使える状態か | 今は GitHub App を使っているので、トークンの期限切れはない（管理画面が毎回、短時間だけ使えるトークンを作る）。App の秘密鍵を作り直したら、スクリプト プロパティ `GH_PRIVATE_KEY` も新しいものにする |
| Python のライブラリ（サイト側） | 大きな版上げが出ていないか | `requirements.txt` は大きな版上げで壊れないよう上限（`<3` など）を付けている。上限を上げるときは手元でビルドを確かめる |
| GitHub Actions の部品 | 古い版の警告が出ていないか | Actions の実行結果に警告が出たら、`deploy.yml`・`check.yml` の `actions/checkout@v5` などを上げる |
| サービスアカウントの鍵 | 使えるか | 鍵にふつう有効期限はない。消された・無効にされたなどで使えなくなったら、新しい鍵を作り、シークレット `GOOGLE_SERVICE_ACCOUNT_JSON` を入れ替えて、古い鍵を消す |
| Drive の容量 | 残りが少なくないか | 管理画面のホーム |
| 検索エンジン | サイトが検索に出ているか | [検索エンジン（Search Console・Bing）](#検索エンジンsearch-consolebing) |
