# 困ったとき（症状から探す）

部員から相談された、エラーの通知メールが届いた、公開しても反映されない、などのときに、症状から原因と対処を探します。

## 症状から探す

管理者が設定やコードを見て直すものです。部員から相談されたときの答え方は、下の「部員からよく聞かれること」にあります。

| 症状・エラー | 主な原因 | 対処 |
|---|---|---|
| 「確認コードを送信」を押しても何も起きない | 画面のスクリプトの構文が壊れている（[画面のスクリプトに書いてはいけない文字列がある](development.md#画面のスクリプトに書いてはいけない文字列がある)） | ブラウザの開発者ツールのコンソールでエラーを確認。`node --test tests/*.cjs` を実行し、直してから `clasp push` とバージョンの切り替え。急ぐときは前のバージョンに戻す（[管理画面を元に戻す](development.md#管理画面を元に戻す)） |
| 「Script Properties が不足しています: …」 | スクリプト プロパティの設定漏れ | 表示された名前のプロパティを設定する（[Script Properties（設定値）](reference/cms.md#script-properties設定値)） |
| 「allowlist シートが見つかりません」「allowlist シートの1行目に email 列が必要です」 | 許可リストのシート名や見出しが違う | シート名を `allowlist`、1行目を `name` / `email` にする |
| 「確認コードを送りました」と出るのに届かない | 許可リストに載っていない（外の人が部員のアドレスかどうかを確かめられないよう、載っていないアドレスにも同じ表示を出し、メールだけ送らない）、迷惑メールに入っている、または Google のメール送信の1日の上限 | 許可リストを確認して追加する（大文字・小文字は区別しない）。載っていれば迷惑メールフォルダを確認してもらう。上限の場合は翌日まで待つ（エラーの通知メールは、確認コード用に残り20通を残して止まるようにしている） |
| 「確認コードの送信回数が上限に達しました」 | 同じアドレスに6時間で5回送った | 最後に送ってから6時間待つ。正しくログインできれば回数はリセットされる |
| 「確認コードの入力が続けて違っていたため、しばらくログインできません」 | 6時間のうちに違うコードを10回入れた（管理者に通知メールが届く） | 最長6時間で解ける。本人の入力間違いでなければ、誰かがそのメールアドレスでログインしようとしている可能性がある |
| 「GitHub Actions の起動に失敗しました」「installation token 取得に失敗しました」 | GitHub App の秘密鍵が違う、App が組織からアンインストールされた、App に Actions の権限がない | 内容はスプレッドシートに保存済み。App の設定とインストール先を確認し、スクリプト プロパティを直してから、もう一度「公開する」 |
| 公開したのにサイトが変わらない | GitHub Actions のビルドが失敗している | 「Actions」で失敗した実行を開き、ログを見る。サービスアカウントの鍵が消されたり無効にされたりしていないか、スプレッドシートや Drive の共有が外れていないかを確認 |
| サイトに画像が出ない | 画像のファイルやフォルダが、サービスアカウントから読めない | Drive のフォルダがサービスアカウントに共有されているか確認 |
| 「Service invoked too many times」「quota」「Limit Exceeded」 | Google の1日あたりの利用上限 | 翌日まで待つ。続く場合は、大量の画像のアップロードなど原因になった操作を確認 |
| 目録の読み取りや誤字チェックが失敗する | Gemini の API キーやモデル名の問題 | `GEMINI_API_KEY` と `GEMINI_MODEL` を確認。誤字チェックが失敗しても公開は止まらない |
| 管理画面の画像に「画像を表示できません」と出る | 非公開の画像をサーバー経由で取れなかった。アップロード直後で Drive のサムネイルがまだできておらず、画像も1.5MBを超えている場合など | 少し待ってから画面を開き直す。続く場合は GAS エディタの「実行数」で `getMediaThumbnails` のエラーを見る |
| 公開に時間がかかる | どこかの段階が重い | コンテンツ用スプレッドシートの `_AdminLog` シートで、その公開の行の `timings` の列を見る。公開処理の開始からの経過秒数が段階ごとに書いてある（`lock`・`read`・`drive`・`sheets`・`history`・`drafts`・`cleanup`・`adminlog`・`compact`・`github`）。`drive` の後ろの「exhibition 0/12」などは、Drive の処理をした項目の数（変更がなければ0）。GAS の「実行数」の画面では、ウェブアプリから呼ばれた処理のログが見られないことがあるため、シートに残している |
| 「ロックのタイムアウト」（Lock timeout） | 保存・公開・画像のアップロードが同時に動いた。ほかの人の操作か、直前の操作がまだ続いていた | 30秒待ってもロックが空かなかった。1分ほど待ってからもう一度。直前の「公開する」が成功していることもあるので、ホームの「公開履歴」も確認する。処理中は「下書き保存」「公開する」を押せないようにしている |
| 「入力が長すぎます。」 | 項目の文字数の上限を超えた | 上限は `ContentModel.js` の各 `normalize…_` 関数にある（例：展示会の概要は1000字）。どの項目かは表示されないので、長い項目から確認する |
| 「現在、ファイルを開くことができません。」 | 複数の Google アカウントでログインしている | 下の「部員からよく聞かれること」の手順を案内する |

## 部員からよく聞かれること

2026年11月まで部員向けのヘルプページ（`docs/index.html`）がありましたが、ほとんど読まれず管理者が直接答えていたので、やめました。答え方をここに残します。管理画面の使い方そのものは、画面の各見出しの横の「？」で説明しています。

| 相談 | 答え方 |
|---|---|
| 「現在、ファイルを開くことができません。」と出る | ブラウザに複数の Google アカウントでログインしているときによく起きる。Chrome のゲストモードで開く（いちばん確実）→ シークレットウィンドウ（Edge では InPrivate）で開く → Cookie を削除して開き直す、の順に試してもらう |
| 確認コードのメールが届かない | 迷惑メールのフォルダとアドレスの打ち間違いを確かめてもらう。登録されていないアドレスでも「送りました」と出る（上の「症状から探す」）ので、許可リストも確かめる |
| 「セッションが切れています」と出る | ログインしてから180分で切れる（操作していても延びない）。再読み込みしてログインし直してもらう。長い作業ではこまめに下書き保存を |
| 共用のパソコンを使った | 使い終わったらタブを閉じてもらう（タブを閉じるとログインが消える） |
| 公開したのに反映されない | 数分かかる。10分待っても変わらなければ「Actions」のビルドを確かめる。項目が「非公開」になっていないかも確かめる |
| 保存した下書きが消えた | 誰かが「公開する」を押すと、全員の下書きが消える。公開の前に声をかけ合ってもらう |
| 画像を選んだのに取り消された | 画像（JPEG・PNG・WebP・GIF・HEIC）だけを選べる。大きい写真は送るときに自動で縮小されるので、縮めなくてよい |
| アップロードした画像が出ない | 「画像の設定」を閉じて開き直す。「画像を表示できません」なら、少し待って再読み込み |
| 手で直した会期表示が元に戻った | 開始日・終了日を変えると、日付から作り直す。日付を決めてから最後に会期表示を直してもらう |
| サイトの住所を押すと違う場所の地図が開く | 会場名と住所で Google マップを検索している。建物名や番地まで正確に書き直してもらう（右側のプレビューでも確かめられる） |
| 活動場所・年間スケジュール・紹介文を変えたい | 管理画面では変えられない。管理者が `src/site_static.json` を直す（[固定の文章や画像を変える](operations.md#固定の文章や画像を変える)） |
