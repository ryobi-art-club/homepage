# 困ったとき（症状から探す）

部員から相談された、エラーの通知メールが届いた、公開しても反映されない、などのときに、症状から原因と対処を探します。

## 症状から探す

管理者が設定やコードを見て直すものです。部員から相談されたときの答え方は、下の「部員からよく聞かれること」にあります。

| 症状・エラー | 主な原因 | 対処 |
|---|---|---|
| 「確認コードを送信」を押しても何も起きない | 画面のスクリプトの構文が壊れている（[画面のスクリプトに書いてはいけない文字列がある](development.md#画面のスクリプトに書いてはいけない文字列がある)） | ブラウザの開発者ツールのコンソールでエラーを確認。構文エラーを直して [テスト](development.md#テスト) で確かめ、[管理画面を反映する](development.md#管理画面を反映する) の手順で修正を反映する。急ぐときは前のバージョンに戻す（[管理画面を元に戻す](development.md#管理画面を元に戻す)） |
| 「Script Properties が不足しています: …」 | スクリプト プロパティの設定漏れ | 表示された名前のプロパティを設定する（[Script Properties（設定値）](reference/cms.md#script-properties設定値)） |
| 「allowlist シートが見つかりません」「allowlist シートの1行目に email 列が必要です」 | 許可リストのシート名や見出しが違う | シート名を `allowlist`、1行目を `name` / `email` にする |
| 「確認コードを送りました」と出るのに届かない | 許可リストに載っていない（外の人が部員のアドレスかどうかを確かめられないよう、載っていないアドレスにも同じ表示を出し、メールだけ送らない）、迷惑メールに入っている、または Google のメール送信の1日の上限 | 許可リストを確認して追加する（大文字・小文字は区別しない）。載っていれば迷惑メールフォルダを確認してもらう。上限の場合は翌日まで待つ（エラーの通知メールは、確認コード用に残り20通を残して止まるようにしている） |
| 「確認コードの送信回数が上限に達しました」 | 同じアドレスに6時間で5回送った | 最後に送ってから6時間待つ。正しくログインできれば回数はリセットされる |
| 「確認コードの入力が続けて違っていたため、しばらくログインできません」 | 6時間のうちに違うコードを10回入れた（管理者に通知メールが届く） | 最長6時間で解ける。本人の入力間違いでなければ、誰かがそのメールアドレスでログインしようとしている可能性がある |
| 「GitHub Actions の起動に失敗しました」「installation token 取得に失敗しました」「GitHub App 用の Script Properties が不足しています」 | GitHub App の設定値が足りない、秘密鍵が違う、App が組織からアンインストールされた、App に Actions の権限がない | 公開時にこのエラーが出た場合は、内容はスプレッドシートに保存済み（全員分の下書きも削除済み）。部員には管理者へ連絡してもらう。ほかの公開エラーでは保存済みと断定しない。App の設定とインストール先を確認し、スクリプト プロパティを直す。保存済み内容の反映は [公開したのにサイトが変わらない](#公開したのにサイトが変わらない) へ。管理画面からの起動も確かめるときは、全員の下書きが消えるため、部員と作業状況を確認してから再公開する |
| 「公開内容が更新されたか、編集の元の内容を確認できません」 | 別の公開、復旧、直前の公開の途中失敗、または基準のない古い画面・下書き | [古い内容からの公開を止められたとき](#古い内容からの公開を止められたとき)へ。自動で最新内容に置き換えない |
| 公開したのにサイトが変わらない | 起動されていない、処理中、ビルド失敗、公開対象の違いなど | [公開したのにサイトが変わらない](#公開したのにサイトが変わらない) で、実行状態から切り分ける |
| 固定の文章や画像を変更・公開したあと、間違いに気づいた | 編集したファイルの内容の間違い | [固定の文章や画像を変える](operations.md#固定の文章や画像を変える) の手順で修正し、もう一度反映する |
| コードを変えて公開したら、表示や動きがおかしくなった | 公開サイトのコードの不具合 | 原因のコードを修正する。変更を取り消すときは [公開サイトのコードの変更を取り消す](development.md#公開サイトのコードの変更を取り消す) |
| 管理画面で間違った内容を公開した | 入力した内容の間違い | 管理画面で修正して「公開する」を押す。公開前に部員と声をかけ合う（全員の下書きが消える）。コードを戻しても掲載内容は戻らない |
| サイトに画像が出ない | 項目や画像の登録、Drive のファイルの削除、共有の問題など | [公開したのにサイトが変わらない](#公開したのにサイトが変わらない) で今回の実行状態を確認する。成功していれば、対象項目が公開中か、使う画像が登録されているか、Drive にそのファイルがあるかを確かめる。画像取得で失敗していれば、対象フォルダの共有を確認する |
| 「保存データのJSONを復元できません」 | 公開状態または指定された下書きの `payload_json`・分割列の欠損や破損 | [保存データを読めないとき](#保存データを読めないとき) で、エラーが示す対象を復旧する |
| 「保存データの形（formatVersion: …）を読めません」「_PublishedState の形（formatVersion: …）を読めません」 | 保存データと、それを読むコードの版が合っていない | [保存データを読めないとき](#保存データを読めないとき) で、対応するコードと反映順を確認する |
| 「Service invoked too many times」「quota」「Limit Exceeded」 | Google の1日あたりの利用上限 | 翌日まで待つ。続く場合は、大量の画像のアップロードなど原因になった操作を確認 |
| 目録の読み取りや誤字チェックが失敗する | Gemini の API キーやモデル名の問題 | `GEMINI_API_KEY` と `GEMINI_MODEL` を確認。誤字チェックが失敗しても公開は止まらない |
| 管理画面の画像に「画像を表示できません」と出る | 非公開の画像をサーバー経由で取れなかった。アップロード直後で Drive のサムネイルがまだできておらず、画像も1.5MBを超えている場合など | 少し待ってから画面を開き直す。続く場合は GAS エディタの「実行数」で `getMediaThumbnails` のエラーを見る |
| 公開に時間がかかる | どこかの段階が重い | コンテンツ用スプレッドシートの `_AdminLog` シートで、その公開の行の `timings` の列を見て、時間のかかった段階を探す（[管理画面の仕組み](reference/cms.md#contentapijs--画面から呼ばれる入口内容と公開) の「公開にかかった時間の記録」） |
| 「ロックのタイムアウト」（Lock timeout） | 保存・公開・画像のアップロードが同時に動いた。ほかの人の操作か、直前の操作がまだ続いていた | 30秒待ってもロックが空かなかった。1分ほど待ってからもう一度。直前の「公開する」が成功していることもあるので、ホームの「公開履歴」も確認する。処理中は「下書き保存」「公開する」を押せないようにしている |
| 「入力が長すぎます。」 | 項目の文字数の上限を超えた | 上限は `ContentModel.js` の各 `normalize…_` 関数にある（例：展示会の概要は1000字）。どの項目かは表示されないので、長い項目から確認する |
| 「現在、ファイルを開くことができません。」 | 複数の Google アカウントでログインしている | 下の「部員からよく聞かれること」の手順を案内する |
| 鍵などの秘密の情報を誤って公開した | ファイル・履歴・ログなどへの混入 | [秘密の情報を誤って公開したとき](#秘密の情報を誤って公開したとき) で失効・交換と公開先の確認を行う |

## 公開したのにサイトが変わらない

1. 公開した時刻、対象の項目、管理画面に出た文言を確認する。
2. GitHub の「Actions」→「Build and Deploy Ryobi Site」で、対応する実行を探し、次の状態に分ける。

   | 実行の状態 | 次にすること |
   |---|---|
   | 実行がない | 管理画面のエラーを確認し、上の症状表の「GitHub Actions の起動に失敗しました」へ進む |
   | 待機中・実行中 | 終了を待ち、成功・失敗に応じて下の行へ進む |
   | 失敗 | 失敗した段階のログを読む。Google からの取得で失敗していれば、対象のスプレッドシート・Drive の共有と、サービスアカウントの鍵が有効かを確認する。保存データのエラーなら [保存データを読めないとき](#保存データを読めないとき) へ進む |
   | 成功 | サイトを再読み込みし、対象項目が管理画面で公開中か、画像が登録されているかを確認する。全体が変わらないのか、一部だけなのかも確かめる |

3. 原因を直したら、保存済みの掲載内容は [公開サイトを反映する](development.md#公開サイトを反映する) の手動実行で反映し、Actions の成功とサイトの対象箇所を確認する。コードの変更がなければコミット・push は不要。

サービスアカウントの鍵が使えないと分かった場合は、Google Cloud Console で新しい鍵を作り、シークレット `GOOGLE_SERVICE_ACCOUNT_JSON` を入れ替えます。上の手動実行で Google からの取得とサイトの反映を確認してから、不要になった古い鍵を消します。漏えいが疑われる鍵は、先に失効して被害の拡大を止めます。

## 保存データを読めないとき

1. 保存・公開を止め、エラー文と発生時刻を控える。変更する前に、現在のコンテンツ用スプレッドシートを Excel に書き出して残す（[バックアップを取る](operations.md#バックアップを取る)）。
2. エラーに応じて、次の対象を確認する。

   | エラー・対象 | 復旧のしかた |
   |---|---|
   | JSONの復元失敗・「公開状態」 | `_PublishedState` の行が対象。スプレッドシートの「ファイル」→「変更履歴」で正常だった時点を探し、`payload_json` と分割列を含めて対象行を復元する |
   | JSONの復元失敗・「下書きID: …」 | `_Drafts` の該当IDの行が対象。同じように分割列までそろえて復元する。ほかの下書きや公開状態は変更しない |
   | `formatVersion` が読めない | [データの約束の「形の版」](reference/data.md#形の版) を確認し、管理画面とサイトのビルドが対応する版か、必要な移行・反映が済んでいるかを確かめる。番号だけを書き換えない。旧版へ戻すときは [管理画面を元に戻す](development.md#管理画面を元に戻す) の条件を確認する |

   セルを空にしたりシートを消したりして、空の内容から始め直さない。シート全体を過去へ戻す場合は、その後のほかの編集も戻るため、戻す範囲と時点を先に確認する。
3. 管理画面を開き直し、公開状態と下書きを読み込めること、復元した文章・作品・画像が意図した内容であることを確認する。公開状態を戻した場合は、手動ビルドでサイトへ反映し、掲載内容を確認する。下書きだけを戻した場合は、公開は不要。

読めるデータが変更履歴に残っていなければ、[控えから内容を戻す](setup.md#控えから内容を戻す) へ進みます。

## 古い内容からの公開を止められたとき

1. 画面を閉じる前に、エラーの詳細の「編集内容を控える」で JSON ファイルを保存する。文章・作品名・作者名・画像の参照が入る。画像本体は含まれないので、元の画像も残す。
2. 再読み込みして最新の内容を開く。自分が変えた部分だけ、控えを見ながら入れ直す。JSON はテキストエディタで読めるが、管理画面へ自動で取り込む機能はない。画像の参照先が消えていたら、元の画像を再登録する。
3. 内容を確認して公開する。古い下書きの読み込みや再保存だけでは、最新の内容を元にした扱いにはならない。

このエラーで止まった公開は、画像・公開内容・他の人の下書きを変更しません。直前の別の公開が途中で失敗した場合は、その処理の変更が残っていることがあります。保存済み内容のサイト反映だけが必要なら、[公開したのにサイトが変わらない](#公開したのにサイトが変わらない)で確認します。

基準の情報を持たない更新前の画面や既存下書きも、同じ手順です。下書き保存はできますが、次の公開で全員分が削除されるため、再読み込み前の手元の控えも残します。

## 秘密の情報を誤って公開したとき

1. 漏れた鍵や認証情報を、その発行元で失効・交換する。
2. リポジトリの現在のファイルだけでなく、過去のコミット・Actions のログ・生成物など、情報が出た場所を確認して削除する。削除コミットを追加するだけでは、過去の履歴には残る。
3. 新しい値を使うスクリプト プロパティやシークレットを更新し、影響した機能を確認する。

## 部員からよく聞かれること

管理画面の使い方は、画面の各見出しの横の「？」で説明しています。ここでは、部員から相談されたときの答え方をまとめます。

| 相談 | 答え方 |
|---|---|
| 「現在、ファイルを開くことができません。」と出る | ブラウザに複数の Google アカウントでログインしているときによく起きる。Chrome のゲストモードで開く（いちばん確実）→ シークレットウィンドウ（Edge では InPrivate）で開く → Cookie を削除して開き直す、の順に試してもらう |
| 確認コードのメールが届かない | 迷惑メールのフォルダとアドレスの打ち間違いを確かめてもらう。登録されていないアドレスでも「送りました」と出る（上の「症状から探す」）ので、許可リストも確かめる |
| 「セッションが切れています」と出る | ログインしてから決まった時間（[Script Properties（設定値）](reference/cms.md#script-properties設定値) の `SESSION_TTL_MINUTES`）で切れる（操作していても延びない）。再読み込みの前に、未保存の文章や作品情報を別の場所へコピーしてもらい、その後ログインし直してもらう。未保存内容の自動復元はなく、画像ファイルの控えも別途必要。長い作業ではこまめに下書き保存を |
| 共用のパソコンを使った | 使い終わったらタブを閉じてもらう（タブを閉じるとログインが消える） |
| 公開したのに反映されない | 数分かかる。10分待っても変わらなければ「Actions」のビルドを確かめる。項目が「非公開」になっていないかも確かめる |
| 保存した下書きが消えた | 誰かが「公開する」を押すと、全員の下書きが消える。公開の前に声をかけ合ってもらう |
| 画像を選んだのに取り消された | 画像（JPEG・PNG・WebP・GIF・HEIC）だけを選べる。大きい写真は送るときに自動で縮小されるので、縮めなくてよい |
| アップロードした画像が出ない | 「画像の設定」を閉じて開き直す。「画像を表示できません」なら、少し待って再読み込み |
| 手で直した会期表示が元に戻った | 開始日・終了日を変えると、日付から作り直す。日付を決めてから最後に会期表示を直してもらう |
| サイトの住所を押すと違う場所の地図が開く | 会場名と住所で Google マップを検索している。建物名や番地まで正確に書き直してもらう（右側のプレビューでも確かめられる） |
| 活動場所・年間スケジュール・紹介文を変えたい | 管理画面では変えられない。管理者が `src/site_static.json` を直す（[固定の文章や画像を変える](operations.md#固定の文章や画像を変える)） |
